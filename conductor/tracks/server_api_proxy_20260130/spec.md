# Track Specification: Server-Side Marble API Proxy

## Overview
This track transitions the Marble API interaction from the client-side to the server-side. By centralizing the API key on the server, we ensure that all users in a shared session can access the same generated worlds, overcoming the Marble API restriction where keys can only interact with worlds they created.

## Functional Requirements
- **Server Refactor:** Update the backend to use Express alongside Socket.io to support both REST endpoints and WebSocket communication.
- **Environment Configuration:** Support `MARBLE_API_KEY` as an environment variable on the server.
- **REST Endpoints:**
    - `POST /api/worlds`: Proxy world generation requests to the Marble API.
    - `GET /api/worlds/:id`: Proxy world retrieval requests to the Marble API.
- **Raw Proxying:** The server will forward the exact JSON response from the Marble API back to the client to maintain compatibility with existing client-side logic.
- **Client Migration:** Update the `apiService.ts` in the frontend to point to the new server endpoints instead of calling the Marble API directly.
- **Security:** Ensure the `MARBLE_API_KEY` is never exposed to the client.

## Non-Functional Requirements
- **Performance:** Proxying should introduce minimal latency.
- **Error Handling:** Server must gracefully handle Marble API errors (4xx, 5xx) and forward relevant status codes/messages to the client.

## Acceptance Criteria
- [ ] Server successfully starts with Express and Socket.io on the same port.
- [ ] `POST /api/worlds` correctly forwards requests with the secret API key and returns raw Marble API data.
- [ ] `GET /api/worlds/:id` correctly forwards requests and returns raw Marble API data.
- [ ] Client-side `apiService.ts` no longer requires an API key in its configuration.
- [ ] New worlds generated by one user are accessible to other users in the same room via the server-side proxy.

## Out of Scope
- Implementing client-side caching of API responses.
- Handling file uploads/binary proxying (the Marble API returns URLs to assets hosted elsewhere, which the client will still fetch directly).
